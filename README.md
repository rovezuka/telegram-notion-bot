# tg-notion-inbox

Telegram-бот, который превращает **любое** сообщение во входящую задачу
в базе Notion. Сортировка и планирование — уже в Notion, бот отвечает
только за быстрый и надёжный захват.

```
Telegram ──► хендлер ──► SQLite (outbox) ──► воркер ──► Notion API
              < 5 мс         durable          retry      POST /v1/pages
```

## Быстрый старт

```bash
git clone https://github.com/<user>/tg-notion-inbox && cd telegram-notion-bot
python3.12 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env      # заполнить токены
python -m app.main
```

## Настройка Notion

1. **Интеграция.** https://www.notion.so/my-integrations → *New connection* →
   тип *Access token* → скопировать *Access token* в `NOTION_TOKEN`.
2. **Доступ.** Открыть в Notion страницу, где будет жить база →
   `•••` → *Connections* → добавить свою интеграцию.
   Без этого шага API вернёт 404 — интеграция не видит ничего, что ей не выдали.
3. **База.**

```bash
   NOTION_TOKEN=ntn_... python -m scripts.bootstrap_notion
   # покажет список доступных страниц, затем:
   NOTION_TOKEN=ntn_... NOTION_PARENT_PAGE_ID=<id> python -m scripts.bootstrap_notion
```

   Схема создаваемой базы:

   | Свойство  | Тип            | Значения                                       |
   |-----------|----------------|------------------------------------------------|
   | Задача    | `title`        | заголовок (первая строка сообщения)            |
   | Статус    | `select`       | Входящие / В работе / Ждёт / Готово / Отменено |
   | Приоритет | `select`       | Без приоритета / Низкий / Средний / Высокий    |
   | Теги      | `multi_select` | из `#тегов` в тексте                           |
   | Источник  | `select`       | Telegram                                       |
   | Срок      | `date`         | из `@завтра`, `@25.12`, …                      |
   | Автор     | `rich_text`    | имя, @username и id отправителя                |
   | Сообщение | `url`          | deep-link на исходное сообщение                |

4. **Бот.** @BotFather → `/newbot` → токен в `TELEGRAM_TOKEN`.
   Свой user id — у @userinfobot, в `ALLOWED_USER_IDS`.

## Использование

```
!! Созвониться с банком по эквайрингу #работа @завтра
```

→ задача «Созвониться с банком по эквайрингу», приоритет *Средний*,
тег `работа`, срок — завтра, статус *Входящие*.

| Синтаксис | Что делает |
|---|---|
| `#тег` | добавляет тег |
| `!` `!!` `!!!` | приоритет низкий / средний / высокий |
| `@сегодня` `@завтра` `@послезавтра` | относительная дата |
| `@пн`…`@вс` | ближайший такой день недели |
| `@25.12` `@25.12.2026` `@2026-12-25` | конкретная дата |

Разметка необязательна, и оригинал сообщения всегда попадает в тело страницы
целиком. Фото, документы, голосовые и видео тоже принимаются: файл остаётся
в Telegram, в задачу попадают метаданные и `file_id`.

Команды: `/help`, `/stats` (состояние очереди), `/retry` (повторить упавшее).

## Архитектура

Между Telegram и Notion стоит транзакционная очередь на SQLite. Хендлер
делает одну быструю запись на диск и сразу отвечает; доставкой занимается
фоновый воркер, который умеет ретраить.

```
pending ──(воркер взял)──► in_flight ──(201 Created)──► done
   ▲                            │
   └──(временная ошибка,────────┤
       backoff 2ⁿ до 10 мин)    └──(8 попыток)──► dead ──/retry──► pending
```

- **Идемпотентность** — `UNIQUE(chat_id:message_id)`: повторный апдейт от
  Telegram не создаёт дубль.
- **Аренда** — строка в `in_flight` держит `leased_until`; если процесс
  убили, задача возвращается в `pending` при старте.
- **Классификация ошибок** — `429`/`5xx`/сеть повторяются с backoff,
  `400`/`401`/`404` уходят в `dead` сразу, повтор им не поможет.
- **Fail fast** — доступ к базе Notion проверяется при старте, а не на
  первом сообщении.

```
app/
├── config.py              настройки (pydantic-settings), единственное место с env
├── main.py                сборка зависимостей, запуск бота и воркера
├── domain/                ядро: модель и парсер, без внешних зависимостей
├── storage/outbox.py      транзакционная очередь на SQLite
├── notion/                httpx-клиент + маппинг в JSON API
├── bot/                   хендлеры, middleware (ни одного вызова Notion)
└── worker/                доставка, ретраи, обратная связь пользователю
```

Зависимости направлены внутрь: `bot` и `worker` знают про `domain`,
`domain` не знает ни про кого. Поэтому вся содержательная логика
тестируется без Telegram, без Notion и без сети.

## Деплой

```bash
docker build -t tg-notion-inbox .
docker run -d --name inbox --restart=unless-stopped \
  --env-file .env -v $(pwd)/data:/app/data tg-notion-inbox
```

Том `data/` обязателен: там лежит SQLite-очередь. Без него при рестарте
контейнера теряются недоставленные задачи.

## Ограничения

- Файлы не заливаются в Notion — API принимает только внешние URL,
  для полноценной выгрузки нужен свой S3-совместимый storage.
- Long polling, один инстанс. Схема с очередью готова к вебхукам —
  меняется только точка входа.
- `Notion-Version: 2022-06-28`. В версии `2025-09-03` базы разделены на
  database и data source, `parent` становится `data_source_id`; правка
  локализована в `mapper.build_page_payload`.
